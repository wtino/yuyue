# 收藏与进度

给主人审的设计。这一轮只写方案，不改功能。

目标是做成 **Bangumi（bgm.tv）和 [Animeko](https://github.com/open-ani/animeko) 那种收藏**，对象换成书：每本书有收藏状态、个人评分、短评、标签、进度、开始和读完日期，并可以按状态浏览、一眼看到进度，附带已有的阅读统计。

约束：

- 不接 Bangumi，不接任何在线书目社区的账号同步。
- 主人不自建、不运维后端。数据可以放在云上，只要那个云不是语阅自己的服务器。
- 三端共用 `core/` 里的一份数据和规则。iPhone、iPad、Mac、Android 只负责界面。

下面第 2 节是代码核对（已实现、半成品、还没有）。第 4 节是建议的数据模型。第 5 节比较云上的存放方式并给出建议，这一项留给主人定。第 6 节是三端界面。第 7 节是可以分开审的实现步骤。第 8 节集中列出要拍板的问题。

## 1. 收藏在语阅里指什么

Bangumi 的收藏是一本书上的 **状态**，不是文件夹。Animeko 用同一套五态（`CollectionPage.kt` 里的 `COLLECTION_TABS_SORTED`）：

| Animeko | 界面文案 | 用在书上 |
|---|---|---|
| `WISH` | 想看 | 想读 |
| `DOING` | 在看 | 在读 |
| `DONE` | 看过 | 读过 |
| `ON_HOLD` | 搁置 | 搁置 |
| `DROPPED` | 抛弃 | 抛弃 |

Animeko 把「抛弃」排在第一格，方便马上看到弃掉的片子。语阅的书架第一件事是继续读，建议顺序改成：**在读、想读、搁置、读过、抛弃**。五态本身保留。

同一条收藏上，Bangumi / Animeko 还有：1–10 的个人评分、短评、标签、看到哪一集、开始和完成日期。语阅对应成：评分、短评、标签、看到哪一章 / 哪一页 / 百分之几（有声书用时间）、开始日期、读完日期。

语阅里已经有的 **合集**（睡前、通勤、科幻）是另一件事：一本书可以同时放进几个合集。合集留下，不拿来模拟五态。一本书可以是「在读」，同时在合集「通勤」里。

## 2. 现有代码核对

印象里的文件都在，而且大部分已经接到界面上。缺的是 Bangumi 那种「一本书的收藏档案」，不是缺一个空壳。

### 2.1 核心里已经有的

操作日志在 `core/yuyue-core/src/store.rs`：每个 `(实体, 字段)` 一份寄存器，写入带混合逻辑时钟，后到的旧时钟盖不掉新的。设备之间交换的是操作，不是整库覆盖。`book/<id>` 的 id 是文件内容 blake3 的前 32 位十六进制（`book.rs` 的 `book_id`）。

| 寄存器 | 字段 | 作用 | 代码 |
|---|---|---|---|
| `book/<id>` | `title` `authors` `language` `format` `isbn` `addedAt` `openedAt` `deleted` `deletedAt` `finished` `finishedAt` `titleEdit` `authorsEdit` | 书架上的一本书。`finished` 是人手标的读完 | `api.rs`、`shelf.rs`、`audio.rs` 的 `record_import` |
| `collection/<id>` | `name` `icon` `order` `usedAt` `deleted` | 合集。id 是 16 位十六进制 | `shelf.rs` |
| `member/<合集>/<书>` | `in` | 在不在这个合集里。两台设备各加一本书，同步后两边都在 | `shelf.rs`，测试 `membership_merges_across_devices` |
| `progress/<书>/<设备>` | `position` = `{section, sentence, fraction, at}` | 这台设备读到的位置。只留最新一笔，不留轨迹 | `api.rs` `save_progress` |
| `bookmark/<书>/<id>` | 位置、摘句、`deleted` | 书签 | `notes.rs` |
| `time/<书>/<设备>` | `s<章节>` = `{read, listen}` 秒 | 每章读了多久、听了多久。一台设备只写自己的，加总不会重复 | `notes.rs` `add_time` |
| `days/<日期>/<设备>` | `<书>` = `{read, listen}` | 阅读统计的按天时长 | `notes.rs` `day_times` |
| `listen/<录音>` | 和哪本电子书对齐 | 听读书的对齐结果，不是收听进度 | `listening.rs` |

`ReadingStatus`（`shelf.rs`）只有三态，而且是 **算出来的**，不是用户选的：

- `finished == true` → 读完
- 人手标过没读完，但进度 > 0 → 在读
- 进度 ≥ 0.995 → 读完
- 进度 > 0，或有 `openedAt` → 在读
- 否则 → 想读

所以今天「想读」表示还没打开。「打开看一眼」会写成在读。读到 99.5% 会静默变成读完。没有搁置，没有抛弃。标成没读完且进度为 0 时，会退回想读（`collections_status_and_undo` 测试就是这样断言的）。

进度百分比在 `api.rs` 的 `fraction`：正文按字数，PDF 按页（`sentence` 是页码），有声书按毫秒（`sentence` 是毫秒）。`BookSummary.progress` 取所有设备里时钟最新的那一笔，文件不在本机时百分比仍然在，因为 `fraction` 写在 `position` 里。章节名需要本机的 manifest，文件不在就拿不到。

`BookSummary.read_minutes` / `listen_minutes` 是按字数估的「还要多久」，不是已经读过的时长。已经读过的时长在 `days/` 和 `time/`。

`records.rs` 能把三态导出成 Goodreads / StoryGraph 的 CSV。没有评分和标签列。

快照（`snapshot.rs`）里，`book/` 和 `device/` 总是带上；`progress/`、`bookmark/`、`time/`、`days/`、`collection/`、`member/` 算在「进度和书签」这一份里。

### 2.2 同步已经有的

`apple/Yuyue/App/Sync.swift`、`android/.../sync/Sync.kt`：每台设备在用户自己的文件夹里写一个 `<设备 id>.yuyue-sync.json`，内容是这台设备见过的全部寄存器（可按开关丢掉进度、笔记或设置）。其他设备整份读入，核心按时钟合并。App 打开时大约每 5 分钟交换一次。

文件夹三种，布局相同，所以 Apple 和 Android 能在同一个 WebDAV 或 Google Drive 里相遇：

| 方式 | Apple | Android | 实际机制 |
|---|---|---|---|
| iCloud | 有。用户在「文件」里选一个 iCloud 云盘文件夹，沙盒用 security-scoped bookmark 记住 | 没有 | **iCloud 云盘里的一个文件夹**，不是 CloudKit |
| WebDAV | 有（坚果云、群晖、Nextcloud 等） | 有 | 用户的 WebDAV 目录 |
| Google Drive | 有，语阅自己的隐藏目录 | 有，同一隐藏目录 | 用户的 Google 账号，Drive API |

另外两个开关：

- **书文件**默认开。文件名 `<书 id>.book.<扩展名>`。id 是内容哈希，同一份文件在哪台导入都是同一本书。手机只在 Wi-Fi 上传下载大文件。`api.rs` 里 `BookSummary.available` 的注释仍写着「文件还不同步」，这句过时了：不同步的是「核心自己不传文件」，传文件是 App 层做的。本机没有文件时，界面写「在别的设备上」。
- **有声书录音**默认关。对齐结果（`listen/`）跟着「进度和书签」走，录音本身太大。

`SyncPart::Reading` 排除的前缀是 `progress/`、`bookmark/`、`time/`、`days/`、`listen/`。`book/`、`collection/`、`member/`、`device/` **不在任何开关里，永远交换**。关掉「进度和书签」时，读完标记和合集仍会过去，读到哪一句不会。

冲突：`store.rs` 只把划线的想法（`mark/` 的 `note`）留给人选。进度、状态、设置是时钟新的赢。想法的冲突有核心 API（`conflicts.rs` 的 `note_conflicts`），界面侧没有搜索到调用，等于核心留了、界面还没接。

### 2.3 三端界面

iPad 没有单独的目标，用 iPhone 的 `PhoneShelf` / `PhoneMe`，`horizontalSizeClass == .regular` 时加宽（继续读的大卡片、网格 4 或 6 列）。Android 平板沿用 `ShelfScreen` 的自适应网格，没有 iPad 那种继续读大卡片。

| 能力 | 核心 | iPhone | iPad | Mac | Android |
|---|---|---|---|---|---|
| 合集的新建、改名、删除、换图标、加入/移出 | 完整，有测试 | `ShelfChooser`、`CollectionPicker`、`PhoneBookInfo` | 同一套 | 合集墙 `MacCollections.swift`、`CollectionPicker`、拖书进合集 | `ShelfSheets.kt` 的 `ShelfChooser`、`CollectionPickerSheet`、`BookInfoSheet` |
| 合集排序 | `reorder_collections` | 编辑模式拖动手柄 | 同 iPhone | 合集墙「自己排的」 | `Library.reorderCollections` 有封装，**界面没有入口** |
| 合集固定在侧栏 | 无此字段 | 无侧栏 | 无 | `PinnedCollections`，存在本机 `UserDefaults`（`shelf.pinnedCollections`），**不同步** | 无 |
| 想读 / 在读 / 读完 | 派生三态 | 标题点开「看哪些书」；长按「标为读完」；多选只能标读完和删除 | 同 iPhone | 侧栏「状态」三行 | 同 iPhone 的筛选和多选 |
| 封面下的进度 | `progress` 0–1 | 一行字（`shelf.showProgress`，本机设置）。长按预览是细线和「还剩多久」 | 宽屏「继续」卡片有进度条、百分比、「还剩」 | 封面下一行字；在读卡片有 `ProgressLine` | 封面下一行字；在读横滑卡片和长按预览有进度条 |
| 打开时接着读 | `progress` 本机优先，没有则用最新一台 | 有 | 有 | 有 | 有 |
| 另一台读到更后面 | `latest_progress` | `ElsewhereCard`（`ReaderReturn.swift`）：设备名、百分比、停在的句子，「留在这里 / 跳过去」 | 同 iPhone | `MacReaderView` 用同一张卡片 | **没有**。`ReaderModel.kt` 读了 `latestProgress`，只在本机没有进度时拿来用，不提示冲突 |
| 阅读器里的进度 | 百分比、本章剩余、目录上的细线 | 有，可在沉浸里隐藏 | 有 | 有 | 有 |
| 阅读统计 | `day_times` | 我的 · 阅读统计：周/月/年，读和听分开，这段时间读完的书，每本书的时长 | 同 iPhone | **没有这一页** | `StatsPage.kt`，和 iPhone 同一套 |
| 评分、短评、标签、搁置、抛弃、开始日期 | 无 | 无 | 无 | 无 | 无 |
| 还没导入文件的书（纸书、想读清单） | 无。书架上的 id 都来自某台设备导入过的文件 | 文件不在本机时显示「在别的设备上」，点开不能读 | 同 | 同 | 同 |
| 从公开书目搜书名、下封面 | 无。封面来自文件，或用户自己换封面 | 换封面是选一张本地图 | 同 | 同 | 同 |

`reading.rs` 是拼音读音，不是阅读进度。`records.rs` 是导出 CSV，不是阅读记录时间线。

合集图标的名字三端约定为 SF Symbol 名（`moon`、`heart` 等），存在核心里，跟着合集走。Android 用 Material 图标对照这套名字（`Shelf.kt` 的 `CollectionIcon`）。

## 3. 建议：在现有的书上加收藏档案

不新建一套「科目表」去平行于 `book/<id>`。阅读器、笔记、进度、同步、快照都以这个 id 为键。收藏状态写成这本书上的字段，三端立刻能筛。

和现在三态的差别是：状态改成 **用户选的**，进度不再偷偷改状态。

### 3.1 寄存器

都写在现有的操作日志里，因此第 5 节推荐的同步方式不用改协议。

`book/<id>` 增加字段：

| 字段 | 值 | 说明 |
|---|---|---|
| `status` | `wish` `reading` `done` `hold` `dropped` | 收藏状态。有这个字段时以它为准 |
| `rating` | 整数 0–10，0 表示未评 | Bangumi / Animeko 的个人评分。0 用 JSON null 清掉，方便时钟合并 |
| `comment` | 字符串，最多 200 字，空则 null | 短评。不是划线里的「想法」 |
| `startedOn` | `2026-11-10` 这种本地日期 | 开始读。用日期不用毫秒，避免时区把「哪一天」翻过去 |
| `finishedOn` | 同上 | 读完的那一天。已有的 `finishedAt`（毫秒）留着，给「今年读完」排序 |
| `manual` | `{chapter, chapters, page, pages, fraction, ms, durationMs}` 里有用的那些 | 只给 **没有阅读位置** 的书用，见 3.4 |
| `entry` | `true` | 只给还没有文件的书目，见 3.5。缺省表示这是一本导入过的书 |

标签不放在 `book/<id>` 的一个数组里。两台设备各加一个标签时，数组会被时钟整个盖掉。用和合集一样的一对一寄存器：

```text
tag/<书 id>/<标签>  ·  on = true / false
```

标签规范化：去掉首尾空白、连续空白并成一个、最多 20 字、一本书最多 30 个、英文按小写比较。删标签写成 `on: false`，这样另一台后加的不同标签还能合并进来。

`finished` 继续写，给还没升级的旧版本看：`done` 写成 `true`，其余写成 `false`。新版本的读法：

1. 有 `status`，用 `status`。
2. 没有 `status`（旧数据）：沿用今天的派生规则，当成一次性迁移。打开书架时如果发现没有 `status`，补写一条，避免每台设备各算各的。

旧版本没有 `status` 这个概念。它仍靠 `finished` 和进度显示三态：搁置、抛弃、以及「有进度的想读」在旧版本上都会看起来像在读。这是混合版本期间的已知限制，不另做一套兼容协议。

### 3.2 状态怎么变

- 人手在收藏卡片里改状态，只写 `status`（以及 `finished` 镜像）。
- **想读**的书第一次 `save_progress`（真的翻页、听了一句，不是仅仅打开）：改成 **在读**，`startedOn` 空着就写成今天。对齐 Animeko「看了就进入在看」。
- 进度到 99.5% **不**再自动改成读过。阅读器和书架给出按钮「标为读过」，对齐 Animeko 看完后的「移至看过」。现在的静默规则删掉，测试 `status` 的断言要跟着改。
- 搁置或抛弃后再打开：进度保留，状态不变。阅读器顶部一条提示「这本书在搁置，改回在读？」，用户点了才改。
- 改成读过：写 `finishedOn`（空着才写今天）和 `finishedAt`。离开读过：清掉这两个完成时间，`startedOn` 保留。
- 改状态不清进度，也不清评分、短评、标签、合集。

### 3.3 一眼能看到的进度

收藏列表上的进度是 **算出来的一行字**，不另存一份「看到第几章」，避免和阅读位置各写各的。

`BookSummary` 增加这些，由核心填好，三端不用各自翻 manifest：

| 字段 | 来源 |
|---|---|
| `status` `rating` `tags` `started_on` `finished_on` | 上面的寄存器。短评不放进列表摘要，点开再读，避免书架把每本书的评论文本都拉下来 |
| `chapter` `chapter_index` `chapter_count` | 本机有 manifest 时，用目录顶层条目对上 `position.section`。没有目录就空着，只显示百分比 |
| `heard_ms` `duration_ms` | 有声书：`position.sentence` 已是毫秒；总长用 manifest 的章节毫秒之和 |
| `pages` | PDF 总页数。现有的 `page` 仍是 1-based 当前页 |
| `progress_at` `progress_device` | 最新那一笔的时间和设备名，列表可以写「昨天 · iPad」 |

显示规则：

| 书 | 有阅读位置时 | 没有阅读位置时 |
|---|---|---|
| EPUB / MOBI / TXT | `42% · 第三章`，有目录再加 `3/28 章`。没有目录就只有百分比 | 想读写「想读」。有 `manual.fraction` 或 `manual.chapter` 时用手动的 |
| PDF | `第 12 / 240 页` | 手动页码，或「想读」 |
| 独立有声书 | `听到 1 小时 12 分 / 8 小时 40 分`，有章节名再附上 | 手动的毫秒，或总时长 |
| 电子书加了听读书（对齐录音） | **仍用电子书的句子位置**，百分比和章节跟「读」相同。不另记一条时间进度。录音在本机时，播放器已经能把句子换成时间，那是播放器的事 | 同电子书 |
| 文件不在这台设备 | 百分比还在（写在 `position` 里）。章节名没有 manifest 就不显示。副文案用「在别的设备上」，点开不能读 | — |
| `entry == true` 的书目 | 不会有阅读位置 | 用 `manual`。副文案是「还没有文件」，不是「在别的设备上」 |

「改进度」：书在本机时，选目录里的一章，调用已有的 `save_progress` 把位置放到那一章开头，不写 `manual`。只有无文件书目才编辑 `manual`。

听和读共用一个位置。书架上已有的「正在听」标记继续叠在这行进度上面。

### 3.4 手动进度

`manual` 只在这本书 **没有任何** `progress/` 记录时参加显示。某台设备一旦写出阅读位置，列表改看阅读位置（人真正读到的地方）。这样两台设备不会有「手动第 3 章」和「读到第 5 章」互相覆盖的问题：手动字段可以被留下，但显示不采用它。

### 3.5 还没有文件的书（建议做，单独一步）

纸书、想买的书、只是想记一笔的书，今天进不了书架。导入流程必须有文件，`books()` 也只列出 `book/` 记录。

建议允许，但放在五态和评分之后，单独一个 PR：

- id 仍是 32 位十六进制，满足 `book_dir` 的检查，但是随机的，不是内容哈希。`entry: true`。
- 不写 `original.*`。本机可以没有目录，封面用现有的「纸色加书名」占位（`BookCover` 已经这样做）。用户若选了一张图，就放在 `books/<id>/cover-own-….jpg`，这张图只在本机，除非打开了书文件同步——无文件书目没有「原文件」可传。封面不同步是这一期接受的限制，不为了封面把图片塞进操作日志。
- 必填书名，作者和 ISBN 选填。ISBN 用已有的 `book/<id> · isbn`。
- 界面文案是「还没有文件」。现有的「在别的设备上」只留给 `entry` 不为 true、而本机没有 manifest 的书。
- 之后导入了文件：按 ISBN 相同，或书名加作者很像，问一句「是不是这一本」。确认后做 `link_entry(条目 id, 文件 id)`：把状态、评分、短评、日期、标签、`manual` **补到文件那条还空着的字段上**（不盖掉文件上已有的进度和笔记），再把条目标成 `deleted` 并写 `replacedBy: <文件 id>`。别的设备看到 `replacedBy` 再做一次同样的补写，补写本身要幂等。笔记和阅读位置本来就在文件 id 上，不用搬。
- 这一期不做「从网上自动建档」。搜索书目是第 5.3 节的可选项，用来填书名、作者、ISBN 和封面，不是用来代替手填。

不建议用两套永久 id（条目 id 永远指向文件 id）。阅读器和笔记只认文件 id，长期挂一个间接层，删除和同步都会绕。

### 3.6 统计

不新做「每次改状态都记一条历史」。操作日志只保留每个寄存器的胜出操作，追加型流水会无限变大。

已经有的够用，再补三个从现有数据算出来的数，不增加寄存器：

- 每个状态有几本（Animeko 标签上的数字）。
- 已有的「今年读完」「这段时间读了多久」。
- 有评分的书的平均分。这是本地算的，没有社区均分。

状态变更时间线（哪天从在读改成搁置）先不做。`startedOn` 和 `finishedOn` 够回答「何时开始、何时读完」。若以后要时间线，用 `event/<书>/<id>` 这种只追加、不改写的实体，单独再议。

Goodreads / StoryGraph 的 CSV 仍只导出三态。搁置和抛弃怎么进他们的列，留到第 8 节。

## 4. 同步时这些字段走哪一条

| 数据 | 怎么走 | 原因 |
|---|---|---|
| `status` `rating` `comment` `startedOn` `finishedOn` `manual` `entry` `replacedBy` | 在 `book/` 上，**永远交换**，快照里也总是有 | 和书名、读完标记一样，关掉「进度和书签」也不该让两台设备的「在读」列表不一样 |
| `tag/` | 同 `member/`：永远交换；快照放进「进度和书签」那一份（`snapshot.rs` 的 `KINDS` 加上 `tag/`） | 和合集成员同一类合并问题 |
| 阅读位置、书签、时长 | 仍是 `SyncPart::Reading`，开关照旧 | 已经如此 |
| 短评冲突 | 把 `book/` 的 `comment` 加进 `store.rs` 的 `watched`，和划线想法一样两份都留着 | 短评是自己写的话。进度和状态继续时钟新的赢 |

快照的「覆盖」会删掉快照里没有的合集（`REMOVABLE` 含 `collection/` 和 `member/`）。`tag/` 同样放进 `REMOVABLE`，否则覆盖之后旧标签还在。

## 5. 数据放在哪里

「没有服务器」指主人不运行自己的后端。收藏可以在云上。下面几种都不需要主人养一台机器，差别在于谁的账号、能不能三端相遇、以及要不要把现在的合并推倒重来。

收藏记录很小（状态、分数、一句短评、标签）。书文件很大，而且已经有一条路。两件事分开看。

### 5.1 比较

| 方案 | 现在有没有 | iPhone / iPad / Mac / Android 能否同一份数据 | 收藏记录 | 书文件 | 要付的代价 |
|---|---|---|---|---|---|
| **现有操作日志 + 用户自己的文件夹**（WebDAV、Google Drive 隐藏目录、iCloud 云盘里选的文件夹） | 有，而且合集成员的合并有测试 | WebDAV 和 Google Drive 可以。iCloud 云盘文件夹只有 Apple | 加字段就跟着走，协议不用改 | 默认已经在传 `<id>.book.<ext>` | 要用户选一种方式。不选就只在本机。iCloud 这一档到不了 Android |
| **CloudKit** | 没有。现有的「iCloud」是云盘文件夹，不是 CloudKit | 到不了 Android | 要第二套存储和合并 | CloudKit 不适合整本 EPUB | Apple 专有。和操作日志两套真相，Android 还得另接一条 |
| **用户自己的 GitHub 仓库** | 没有 | 理论上可以，只要 App 拿用户的 token 去读写仓库 | 操作日志的 JSON 可以作为一个文件提交，等于新做一个 `SyncFolder` | 仓库不适合成百 MB 的书，Git LFS 有配额和认证 | 要做 GitHub 登录或 PAT，处理二进制、冲突提交、API 速率。Gist 更小，单文件约 1 MB 量级，书文件放不下，只够日志 |
| **Supabase / Firebase 免费档** | 没有 | 可以 | 行，但是要把寄存器改成他们的表，或只把 JSON 当一个文档 | Storage 桶可以放书，免费档有容量和流量上限 | 主人不托管，可是 App 依赖别人的项目：配额、停服、条款、钥匙打进安装包。隐私文案今天写的是「语阅看不到，只在你的设备和你选的网盘之间」。还要把时钟合并重写一遍 |
| **公开书目 API**（Open Library、Google Books 等） | 没有 | 查询不存收藏 | **不存放收藏**。只在添加书时填书名、作者、ISBN、封面 | 不放书文件 | 见 5.3。豆瓣没有可用的开放 API |

### 5.2 建议

**收藏的唯一真相继续放在 `library.db` 的操作日志里，用现有的 WebDAV / Google Drive / iCloud 云盘文件夹交换。** 不把 CloudKit、GitHub、Supabase、Firebase 引进第一期。

理由：五态、评分、标签都是寄存器上的几个字段，现有合并已经能表达「两台设备各改各的，时钟新的赢；标签和合集成员按条合并」。换一套 BaaS 要重写这一层，还要一个账号体系，并且和现在的隐私说明相反。CloudKit 解决不了 Android。GitHub 仓库可以以后做成第四种 `SyncFolder`（只同步那个 JSON，书文件仍走网盘），不该为了收藏先做。

用户什么都不选时，数据和今天一样留在本机，这是默认，不是唯一允许的去处。

### 5.3 添加书时的书目查询（可选，不接 Bangumi）

这层只负责 **搜索和封面**，查完就写进本地的 `book/` 记录。不保存对方的账号，不回写，不把对方当成收藏的宿主。

| 来源 | 能用来做什么 | 认证 | 建议 |
|---|---|---|---|
| [Open Library Search API](https://openlibrary.org/dev/docs/api/search) | 书名、作者、ISBN、封面（`covers.openlibrary.org`） | 基本搜索不需要钥匙 | **默认的一个**。请求由用户点「查找」触发，不在后台扫 |
| Google Books Volumes API | 书名、作者、ISBN、封面 | 需要 API key，有免费配额 | 作为第二个。钥匙不要写进仓库。构建时配置，或设置里让用户填自己的 key。没配就只显示 Open Library |
| 豆瓣及同类中文站点 | 中文书收录比上面两个好 | 开放 API 已关闭 | **不做**。不抓网页，不走非公开接口。中文书查不到就手填，这和今天改书名、换封面是同一条路 |

封面下载到这本书的目录，之后是否上云，沿用「书文件」那个开关。查询失败只影响预填，不影响手填和收藏。

中文封面会经常查不到。方案接受这一点，不为此去接豆瓣。

## 6. 界面

沿用现在的组件：iOS 的 `YYGroup` / `YYRow` / sheet，Mac 的侧栏和合集墙，Android 的 `YYGroup` / `ModalBottomSheet`，进度条用已有的 `ProgressLine`。不新增底部 tab。书架的标题已经能切换「看哪些书」，收藏就是这里的状态从 3 个变成 5 个。

### 6.1 按状态看，并看见进度

- **iPhone**：点标题，`ShelfChooser` 的「按状态」加上搁置、抛弃，每行右边是本数。选中「在读」或「搁置」时，网格换成列表行：封面、书名、作者、评分（有的话）、`ProgressLine`、第 3 节那一行进度、设备名（最新进度不是这台时）。其他状态仍用封面网格，封面下保留现在那一行字。`shelf.showProgress` 继续管封面下的字。
- **iPad**：同一页。宽屏时列表两列，「继续」大卡片留在「全部」顶上，卡片里已经有进度条，补上章节或时间。
- **Mac**：侧栏「状态」从三行改成五行，本数用现有的 `sidebarRow`。选中某个状态时，主区用和 iPhone 相同的列表行，不另做窗口。合集墙、拖书进合集、固定到侧栏都不变。固定侧栏仍只存在这台 Mac。
- **Android**：和 iPhone 同一套，改 `ShelfChooser` 和 `ShelfScreen`。平板宽了就两列列表，不单做布局。

多选条今天只有「标为读完」和「删除」。加上「改状态」，一次把选中的书写成同一个状态。

### 6.2 编辑一本的收藏

扩展已有的「编辑信息」，不新做页面。

- iPhone / iPad：`PhoneBookInfo`
- Mac：现有的编辑信息面板（`editing` 那条）
- Android：`BookInfoSheet`

里面按这个顺序：

1. 状态五选一，当前项用现在的强调色胶囊。
2. 评分：五颗星，每颗 2 分，存 1–10。再点已选的分数就清掉。未评不显示星星的填充。
3. 短评：单行开始，点开再多行，200 字。
4. 标签：已有的标签可点掉；输入时提示这本书以外用过的标签。
5. 开始日期、读完日期：点了才改，清空用单独的按钮。
6. 进度一行，加上「改进度」（本机有文件时选章节或页；无文件书目才填数字）。
7. 合集一行，就是现在的「加入合集」。

长按菜单在「标为读完」旁边保留，它只是把状态写成读过或从读过改回在读的快捷方式。

阅读器：进度跨过 99.5% 时，在现有的胶囊附近放「标为读过」，点了才写。搁置和抛弃打开时用一条细提示，样式靠近 `ElsewhereCard`，不挡翻页。

### 6.3 Android 上的「另一台读到更后面」

Apple 已有完整卡片。Android 的阅读器在本机已有进度时会忽略另一台。这是进度体验的缺口，单独一个小 PR 把 `ElsewhereCard` 的行为补上，不和收藏字段绑在一起。

### 6.4 统计

iPhone 和 Android 的阅读统计页加上五个状态的本数，以及有评分时的平均分。Mac 今天没有这一页。建议 Mac 先不做新的统计窗口，侧栏本数已经能回答「在读有几本」。若要和手机一样的柱状图，单独一步，数据用现成的 `day_times`。

### 6.5 添加一本还没有文件的书

在「看哪些书」或导入菜单里加「记一本书」。表单：书名、作者、ISBN、状态（默认想读）。旁边一个「查找」：按第 5.3 节查 Open Library，有 Google Books key 再查一次，结果列出来给人选，选中后填进表单，封面能下则下。查不到就留下手填的字。这一步依赖 3.5，排在后面。

## 7. 实现步骤

每一步都可以单独审、单独合。核心改动带 `cargo test` 里的新测试；界面改动沿用现有的书架和编辑信息，不顺手改无关布局。

1. **本文件。** 只讨论，不改行为。
2. **五态。** `ReadingStatus` 增加搁置、抛弃；`status` 字段和迁移；`finished` 继续镜像；删掉 99.5% 静默读完；想读在第一次 `save_progress` 时变成在读。改 `shelf.rs` 的测试。UniFFI 枚举变了，三端绑定一起再生，但这一步可以先只改核心和测试。
3. **评分、短评、日期、标签。** 寄存器、`BookSummary` 的新字段、`tag/` 进快照的 `KINDS` 和 `REMOVABLE`、短评进 `watched`。核心测试覆盖「两台设备各加一个标签，同步后两个都在」。
4. **进度一行。** `BookSummary` 补章节、页数、有声书毫秒、最新设备名。有声和电子书的显示规则按 3.3 的表做测试。
5. **三端收藏界面。** 筛选五态、在读/搁置列表行、编辑信息里的评分短评标签日期、多选改状态、阅读器「标为读过」和搁置提示。iPhone 与 iPad 是同一份 `PhoneShelf`。Android 对齐。Mac 只加侧栏行和列表行。
6. **Android 进度冲突卡片。** 对齐 `ElsewhereCard`。
7. **无文件书目。** `entry`、`manual`、`link_entry` / `replacedBy`，以及「记一本书」表单。
8. **书目查找。** Open Library；Google Books 仅在有 key 时。设置里说明钥匙从哪来。不接豆瓣。
9. **统计上的五个数字，以及 CSV。** 状态本数和平均分；Goodreads / StoryGraph 怎么放搁置和抛弃，等第 8 节定了再写。

第 2–4 步是后面所有界面的前提。第 7–8 步可以整段往后放，甚至不做，五态和进度已经能用在已经导入的书上。

## 8. 请主人定的事

1. **数据放哪。** 建议：收藏写进现有操作日志，用现在的 WebDAV、Google Drive、iCloud 云盘文件夹同步；不引入 CloudKit、GitHub、Supabase、Firebase。是否同意？若不同意，优先想要哪一种，第 5.1 节的代价是否接受？
2. **还没有文件的书做不做。** 建议做，但放在第 7 步：随机 id、`entry: true`、导入文件后合并到文件 id 并留下 `replacedBy`。封面不进操作日志。是否同意这个范围？
3. **书目查找做不做，做到哪。** 建议只做 Open Library，Google Books 作为有钥匙才出现的第二来源，不做豆瓣。中文书会经常查不到。是否接受？
4. **五态的顺序和自动变化。** 建议顺序是在读、想读、搁置、读过、抛弃。想读一有进度就变成在读。读到头只提示「标为读过」，不自动改。搁置后再打开要用户确认才回到在读。有没有要改的？
5. **评分。** 建议存 1–10、界面五颗星。是否要半星以外的档，或干脆不要评分？
6. **短评。** 建议最多 200 字，冲突时两份都留着（和划线想法同一机制）。旧的想法冲突界面还没接上，短评冲突是一起做界面，还是第一期先让时钟新的赢？
7. **合集和收藏的关系。** 建议保持两套：合集是文件夹，状态是收藏。不把「想读」做成一个特殊合集。是否同意？
8. **导出。** Goodreads 的书架列没有搁置和抛弃。建议搁置、抛弃先导出成 `to-read`，StoryGraph 若有 `did-not-finish` 再把抛弃放过去。还是这一期干脆不改 CSV？
9. **Mac 的统计页。** 建议第一期只在侧栏显示每个状态的本数，不做和手机一样的柱状图。是否够用？
